# Full implementation review · 2026-11-07

The local testnet implementation passed this review after fixes. No blocking defect remains within the reviewed scope. Public hosting, mainnet, wheel-only installation, and a native Hermes Desktop panel are outside this checkpoint.

The review covered the seller state machine, immutable contracts, wallet authentication, payment authorization, chain evidence, encrypted persistence, runtime isolation, independent buyer/plugin boundaries, owner authoring flow, browser recovery, and responsive UI. Seller, buyer, and frontend reviews ran independently. The buyer reviewer also checked the new seller recovery implementation.

## Fixed findings

| Finding | Change and verification |
| --- | --- |
| Unknown executions could block the seller permanently | Poll the original run; recover a lost run ID only through exact credential-scoped admission identity. No repeated run submission. Missing evidence stays unknown. |
| Old backups could falsely report a paid order as unpaid | Locked views expose uncertainty, including pre-admission snapshots. Buyer budget remains reserved. Confirmed payments survive late execution responses; paid results can be restored after the deadline. |
| Recovery endpoints were unavailable under a restore lock or dependency outage | Keep local reads and authenticated owner recovery available. Readiness and restore gates still block execution and settlement. |
| An old payment could fall outside the bounded block scan | Accept an optional transaction hash as a hint only after exact USDC nonce, payer, payee, amount, canonical receipt and depth checks. Invalid hints preserve uncertainty. |
| Disconnect could be undone by delayed wallet responses | A persisted per-origin generation and atomic challenge invalidation reject in-flight challenge and verification responses after disconnect. |
| A rejected first quote could lose its recovery handle | Return the already persisted purchase ID as `quote_unknown`; retry with the same idempotency key. |
| Unsigned quotes were blocked after reload; concurrent tabs could sign twice | Persist unsigned/signing intent and coordinate signing with a Web Lock. Legacy unknown records remain protected. Rejected prompts allow another explicit attempt. |
| Narrow buyer approval layout overflowed | Wrap the complete service revision and inspect the buyer/Studio screens at 360px. Also correct empty-state and unsupported-role errors. |
| Normal terminal shutdown printed a traceback | Treat an explicit keyboard interrupt as CLI exit 130. |

## Limits

- Wallet checks use an automated EIP-1193 bridge with dedicated test keys held in Node. Human acceptance in a wallet extension has not been exercised.
- Recovery faults were injected into ledger copies; no live process was killed during a new settlement. Missing retained run records remain unknown. Old block ranges require a verified receipt hint.
- Restored ledgers never unlock automatically. An incomplete backup may omit entire later orders, so visible-order recovery cannot prove the whole ledger is safe to resume.
- The pinned runtime is Hermes v0.23.0 on ARM64. Its admission-database integration requires revalidation before changing the Hermes version. The confirmation policy is two Base Sepolia L2 blocks, not Ethereum L1 finality.
- The current model credential is access-token-only and cannot refresh itself. External publication remains deferred at the user's request.
